# تدقيق حزم البرامج — إعداد فحص الأمان لمرة واحدة

**التاريخ:** 2026-11-08  
**المرحلة:** G0 قيد العمل وغير مقبولة.

تم إعداد إجراء GitHub Actions مؤقت يولّد فهرس حزم بصيغة CycloneDX ونتائج فحص ثغرات Grype. الأداة تتأكد من أن نسختي Syft وGrype تم تنزيلهما وفق **SHA256 من أصول الإصدارات المنشورة**، دون تحديث شفرة المشروع أو استيراد الأكواد من GitHub مجددًا. تُنفَّذ فحوص للبيئتين:

1. بيئة Python 3.11 تُثبَّت فيها الحزم الست من `requirements-ci.lock` باستخدام `--require-hashes` ثم تُفهرس.
2. كامل ملفات المستودع بما فيها المصادر المستوردة المجمدة، ويُفهرس ما يمكن لأداة Syft التعرف عليه من الحزم والإصدارات.

تستخدم Grype قاعدة بيانات ثغرات حيّة وقت الفحص. **تحديث قائمة الثغرات ليس تحديثًا لمشاريع المنبع**؛ تبقى الشيفرات ثابتة. يوضّح التقرير العناصر التي أظهرها الفهرس وأي ثغرات عامة موجودة، بما في ذلك الحالات التي تحتاج إلى مراجعة يدوية.

بعد نجاح الفحص، يجري إنشاء فرع مراجعة مستقل وحذف Workflow من الفرع الجديد حتى لا يبقى إجراء مؤقت ذي صلاحيات كتابة. لا تدمج النتائج إلا بعد فحص تغطية الفهرسة والمخرجات والتأكد من عدم تضمّنها معلومات خاصة.

## حدود لا يجوز تجاوزها

- الفحص الآلي ليس اختبار اختراق ولا تحليلًا معمقًا لكل سطر من الشيفرة أو كل صلاحية.
- لن يثبت سلامة أدوات MQL5/Wine/MT5 أو CUDA أو Linux أو مكتبات ML غير المثبتة.
- غياب الثغرات المطابقة في Grype لا يعني غياب الثغرات أو أمانًا مطلقًا، لأن تغطية DB ومطابقة الأسماء والإصدارات محدودة.
- G0 وG1 وما يليها لا تتغير آليًا. نحتاج مراجعة قانونية لرخص المصادر والاعتماديات.
- لا يؤدي الفحص إلى تحميل أوزان Qwen/Chronos أو الاتصال بالوسيط أو إجراء تداول.

## كيف نستخدم النتيجة

اقرأ `planning/security/scans/one_time/triage_summary.json`، افحص قائمتَي `ci_environment` و`repository_sources`، ثم صنف كل finding: **يستخدم فعليًا / مصدر مؤرشف فقط / غير مؤكد**. تُفتح مهمة إصلاح مستقلة لكل تعرض حقيقي، ويُوثَّق سبب عدم التأثر في الحالات الأخرى. لا نتبع تغييرات المنبع آليًا؛ نصحح الكود المعتمد داخليًا.
