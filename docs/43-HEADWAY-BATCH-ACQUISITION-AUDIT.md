# تدقيق دفعات أسعار Headway قبل التقييم

يدقق `scripts/audit_headway_tick_batches.py` سجل تشغيل مصدّر MT5
وملفات CSV الخام معًا. يفحص حدود كل دفعة وعدد صفوفها وبصمتها وسلامة
Bid/Ask وترتيب الأوقات. يفصل الطلب الذي أعاد صفر صفوف عن الطلب الذي
لم يعد بنتيجة موثقة. الفجوات المقاسة هي بين التحديثات المرصودة، وقد
تشمل إغلاق السوق أو فقد بيانات، ويحتاج تفسيرها إلى دليل منفصل.

يعتمد التدقيق على دفعات الدقيقتين التي ينشئها
`scripts/export_headway_ticks.py --batch`. استعمل مجلدًا جديدًا لكل
محاولة واحفظ سجل الخرج كاملاً. تستطيع المحاولة المستأنفة تخطي ملفات
موجودة مسبقًا، لذلك يظهر الملف المتخطى دون إيصال في سجل المحاولة الذي
يُدقق. احتفظ بالسجلات الأصلية كي تظل الدفعات مرتبطة بطلباتها.

```bash
python scripts/audit_headway_tick_batches.py \
  artifacts/headway-session-expanded-20261118 \
  artifacts/headway-session-expanded-export-20261118.log \
  artifacts/headway-batches-audited.json \
  --start 2026-11-18T13:00:00+00:00 \
  --end 2026-11-18T14:28:00+00:00
```

الحدود هنا تسميات ساعة MT5 الأصلية مكتوبة بصيغة تقبلها الواجهة.
تحويلها إلى UTC يحتاج دليلًا مستقلًا للفترة المطلوبة. يحتفظ التقرير
بملف لكل دفعة ناجحة ويميز الحالات الآتية:

| الحالة | المعنى |
| --- | --- |
| `saved_verified` | ملف صالح وعدد صفوفه يطابق سجل الطلب |
| `reported_empty` | سُجل طلب أعاد صفر صفوف |
| `file_without_receipt` | ملف صالح دون نتيجة طلب في السجل المحدد |
| `missing_reported_file` | سجّل المصدّر حفظ ملف والملف غائب |
| `unaccounted` | لا ملف ولا نتيجة طلب، بما فيها الطلب المنقطع |

ترفض الأداة تداخل أسماء الدفعات، والصفوف خارج حدود الطلب، وتناقض العدد
مع السجل، والسعر غير الصالح. وتعدّ التحديثات ذات المللي ثانية نفسها
وتكرار الأربعة حقول المصدّرة دون حذف صف. يخرج الأمر بالحالة 2 بعد
كتابة تقرير النقص، وبالحالة 0 عند توثيق نتيجة كل طلب بصورة متسقة.
حالة الخروج 0 تثبت سلامة محاسبة الطلبات فقط. يظل التأكد من نشاط السوق
وموثوقية ساعة الوسيط وتغطية نافذة التقييم وتكاليفها مطلوبًا.

## مطابقة محاولات الجمع المتعددة

استخدم مجلدًا منفصلًا لكل محاولة، يحوي `batches/` و`export.log`. أعد طلب
الفترات التي لم تُوثّق نتائجها في مجلد جديد. ادمج **إيصالات الطلبات** على
حدود الدقيقتين الأصلية باستخدام `scripts/reconcile_headway_attempts.py`.

`--attempt DIRECTORY NATIVE_START NATIVE_END` لكل محاولة.

تُحسب الدفعة المتطابقة مرة واحدة، مع حفظ نتائج كل محاولة. إذا تغيرت
البصمة أو تناقض العدد أو اختلفت حالة فارغ/محفوظ، يخرج الأمر بالحالة 2
ويترك التعارض ظاهرًا للمراجعة. لا يعد تقرير «صفر صفوف» إثباتًا لإغلاق
السوق. التقرير لا يحوّل الوقت ولا يحسب نتائج الاستراتيجية.

## فصل عينات الساعة عن الدفعات المغلقة

قد يرجع الوسيط صفوفًا صالحة لطلب تنتهي نافذته بعد وقت الطلب.
هذه الصفوف مفيدة لمطابقة الساعة، لكن نجاح الطلب لا يثبت اكتمال النافذة.
احفظ وقت الطلب من الساعة المتزامنة، وانتظر انقضاء النهاية التي يشير
إليها فرق الجلسة المرصود قبل إعادة طلب النافذة. احفظ عينة الساعة
والدفعة المغلقة في مجلدين منفصلين. قد تصبح العينة الأولية بادئة لملف
الدفعة المكتملة؛ لا تجمعهما ولا تحذف دليل الرصد.

في أول يوم من النافذة المسجلة، تضمنت عينة إحدى الدفعات المبكرة 106
تحديثات. أعاد الطلب بعد انقضاء النهاية 860 تحديثًا، وطابقت البايتات
الأولية محتوى العينة كما هو. بعد استبدالها في قائمة الدفعات المغلقة،
حُفظت 365 دفعة تضم 354,931 تحديثًا. اجتاز ملف M15 المرافق فحص
236 شمعة، وطابقت الأسعار الأربعة في الشموع الـ48 المتداخلة تجميع
تحديثات Bid على الساعة الأصلية. لا تثبت هذه المطابقة فرق UTC لكامل
الفترة ولم يُحسب أي أداء خلالها. سجل التصحيح المحلي في
`artifacts/prospective-holdout-20261118/acquisition/20261123/closed-window-evidence.json`.

يطبق `scripts/collect_closed_headway_batches.py` هذا الفصل عند جمع
الدفعات بواسطة Wine. مرّر إيصال الساعة الحديث عبر `--receipt` وحدود
الساعة الأصلية عبر `--start` و`--end`. يتطلب الأمر مزامنة ساعة الجهاز
ويمنع الطلب حتى تمر ثانيتان على نهاية النافذة وفق الفرق المرصود.
يحفظ `closed-request.json` وقت الطلب وبصمة إيصال الساعة ونتائج تدقيق
المصدّر. يثبت الإيصال أن الطلب أُرسل بعد النهاية وفق فرضية فرق الجلسة؛
تبقى سلامة تغطية السوق وتحويل توقيت الفترة كلها شرطين منفصلين.

عند تجميع التقارير، استخدم `--guarded-attempt DIRECTORY CLOCK_RECEIPT`
للمحاولات التي حفظت `closed-request.json`. يعيد أمر المطابقة فحص وقت
الطلب وملف الساعة وسجل التصدير وبصمات CSV، ويسجل بصمة إيصال الطلب.
تبقى المحاولات الأقدم التي تمرر عبر `--attempt` ظاهرة دون هذا الحقل؛
ربط إيصال دفعة واحدة لا يرفع درجة إثبات الدفعات الأخرى.
