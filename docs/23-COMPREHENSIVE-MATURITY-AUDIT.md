## 4) أهم الجوانب الناجحة
- نطاق **XAUUSD فقط**، قرار `NO_TRADE`، تجميد نسخ المصدر، فصل التداول الحقيقي عن البحث، وإبقاء الوكلاء دون أداة `place_order`.

- ملفات مورّدي المصدر متاحة دون العودة إلى upstream، وهناك فحص SHA ومسارات قانونية مبدئية. Archive لا يعني استغلال الشيفرة أو تشغيلها.

## 5) فجوات مهدّدة علمياً أو تشغيلياً

### F01 — لا يوجد أساس بيانات متاح للتدريب (حرج)
الـCSV القابل للفحص لا يثبت صلاحية توقيت خادم MT5 أو سعر تنفيذ Tick/Bid/Ask. يلزم `broker_symbol` و`contract specs` لكل فترة، وإثبات تحويل المنطقة الزمنية وDST، وفحص فترات الغياب، والتراخيص والمصدر المستقل. لا تدريب حقيقي قبل G1. المهام #10، #13–#18.

### F02 — الاستقرار الأمني غير مكتمل (حرج)
تجميد Git SHA للمصادر لا يثبّت حزم Python العابرة أو GitHub Actions. تثبيت `pip install -e '.[dev]'` مع حدود إصدارات و`actions/checkout@v4` قابل لتغيير النتائج. لا SBOM أو scanner متكامل؛ حماية `main` معطلة. إلغاء تحديث المنبع يقتضي **عملية خاصة بنا لرصد الثغرات وتصحيحها في النسخة الداخلية**؛ لا يعني تجاهلها. المهام #2، #9، #11.

### F03 — الفجوة بين سلامة الأرشيف وسلامة التشغيل (مرتفع)
الأرشيف الكامل 584 ملفاً لم يُدمج فعلياً ضمن مكوّنات تشغّل مستورداتها وتنجح في اختبار Contracts. يوجد 14 ملفاً متطابقاً بين نسختي TradingAgents/Midas (~3.74 MB)؛ يجب تجنب مسارات Import مختلطة. لا تنفّذ شيفرة `vendor/research_refs/` غير الموثوقة لمجرد وجودها. المهام #6–#8، #30.

### F04 — أهداف التدريب لا تعني أرباحاً (حرج بحثياً)
الوسوم القائمة TARGET/STOP/TIMEOUT/AMBIGUOUS مبنية على OHLC افتراضي وتصرّح `executable_pnl_verified=False`. لا Bid/Ask أو انزلاق/عمولة/تبديل/قيود تنفيذ؛ لذلك لا يجوز استخدامها لإعلان عائد أو تقويم الأفضلية. لا Trainer LightGBM/CatBoost حتى الآن. المهام #19–#26، #35–#38.

### F05 — قياس التفوق العلمي غائب (حرج)
لا تجربة واحدة تخص مشروعنا تقارن النموذج بـAlways NO_TRADE، Random Walk، قواعد سعرية بسيطة، والمقارنات الإحصائية بعد التكاليف. لا Trial Ledger أو Holdout مغلق فعلي؛ لا يمكن قياس Brier/ECE/Sharpe/DSR/Drawdown على نتائج مشروعنا. لا يسمح بتحسين النموذج بناءً على نتائج Aurum الأصلية بوصفها أدلة خاصة بنا. المهام #22، #35–#38، #56.

### F06 — التنفيذ والمخاطر في مرحلة محاكاة وحدات (حرج)
الدالة `assess_paper_proposal` ليست تصريحاً بإرسال أمر. `broker_order_check_ok` مجرد Boolean مقدم من الداعي؛ لا OrderCalcProfit/OrderCheck فعلي ولا حجز مخاطرة ذري للطلبات المتزامنة ولا دفتر أوامر durable/idempotency ولا reconciliation عند نتيحة غامضة، ولا تحوط من فجوة السعر. لا ربط Demo. المهام #39–#43.

### F07 — تشغيل النماذج والوكلاء غير مثبت (مرتفع)
ثلاث مراجعات أوزان مثبّتة ميتاداتياً لكن لا أوزان محملة ولا Runbook لبطاقة الرسوم/RAM/حجم السياق/latency. لا Qwen محلي موصول بعقود Gold-only، ولا اختبارات Prompt Injection على المدخلات الخارجية. لا ينبغي زيادة وكلاء LLM قبل إثبات تفوق quant+agents على quant-only في تجربة منضبطة. المهام #27–#34.

### F08 — الأرشفة تضخم حجم Git دون تحسين النواة (متوسط)
640/723 ملفاً (~88.5%) Vendor. هذا مقبول إذا كان الهدف الحفظ، لكن يضاعف عبء إدارة الترخيص وفحص الاعتماديات ولا يقيس الجاهزية. نُبقي نسخ المنبع المجمدة بصفتها محفوظة ونستخدم *وحدات مختارة فقط* بعد اختبارها. لا ننقل مشاريع كاملة جديدة حالياً.

### F09 — الحوكمة لا تطابق البرمجة المنفذة (مرتفع)
كل الـ52 مهمة `todo` و`owner=null` و`estimate=TBD` و`evidence=[]` في سجل المهام؛ ولا Labels/Milestones على GitHub رغم وجود metadata داخل JSON. حدثت PRs أنجزت أجزاءاً من المهام، لكن لم يُسجّل ذلك بنمط `in-progress/partial/blocked/accepted`. تحديث ملف `docs/13-STATUS.md` لا يزال يذكر 117 اختباراً رغم نجاح 120 على آخر Main. يجب مصالحة الإنجاز الفعلي وفق شروط القبول لا مجرد عدد الـPRs.

### F10 — التشغيل والتعافي غير مختبرين (مرتفع)
لا بيئة تدريب pinned أو Benchmark للأداء GPU/CPU، ولا حفظ/استعادة مجربة للأوزان أو البيانات، ولا كاشف Drift معتمد، ولا مراقبة 24/5 أو تمرين انقطاع الشبكة/الجهاز. المهام #44–#47، #58–#59.

## 7) اختبارات القياس المطلوبة قبل الانتقال

**البيانات:** تغطية ساعات السوق/الرمز/التوقيت، تباين السعر بين الوسيط والمصدر المرجعي، معدل قيم invalid، `available_at`، قياس spread/tick والحقوق القانونية.  
**التنبؤ:** Brier/LogLoss، Calibration/ECE، Coverage/quantile scoring، نسبة NO_TRADE، الأداء حسب الجلسة والنظام.  
**التداول:** Net Expectancy + CI، trade count/independence، turnover، hit-by-cost stress، max drawdown، risk-adjusted return، غياب future leak، قدرة التعافي من انقطاع التنفيذ.  
**العمليات:** CI + coverage + SBOM، تغيير التوزيع، كلفة الاستدلال/الزمن، جودة Logbook، Restore Drill، أحوال الأمر `unknown/partial/reconciled`.  
**قبول المنتجات:** Holdout يستعمل مرة واحدة، يدوّن عدد التجارب، لا يمر Live فقط لأن Backtest أخضر، وموافقة بشرية لكل Gate.

## 8) اعتبارات الامتثال والنزاهة

- ترخيص الكود لا يمنح تلقائياً حق نسخ بيانات السوق أو نشر أوزان النماذج، ويجب مراجعة شروط الوسيط وأي قيود على التداول الآلي والتشغيل المحلي.
