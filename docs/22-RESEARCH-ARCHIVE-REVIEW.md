## ما ثبت فعليًا
- استُخدمت Git SHAs ثابتة عند الاستيراد الأول ولم تُستدعَ update/fetch لاحقًا.
- حفظنا الملفات والتراخيص دون تعديل، مع رفض روابط symlink وبعض الأنماط المعروفة للأسرار. فحص الأنماط **ليس** تدقيقًا أمنيًا كافيًا.
- `scripts/verify_research_refs.py` يتأكد من قائمة المصدرين ومن تطابق المحتوى مع Manifest. لا يستورد أو يشغّل أي شيفرة خارجية.
- أُزيل Workflow الأرشفة ذات الاستخدام الواحد أثناء إنشاء فرع المراجعة؛ لن يُعاد جلب المنبع تلقائيًا.
- لا توجد صلاحيات API أو إعدادات تثبيت تؤدي إلى استدعاء المكتبتين داخل `src/goldintel`.

## احتياطات مهمة قبل إعادة استخدام أي خوارزمية

**oos-lab:** عدد المستخدمين والإصدارات الحديثة محدود. وجود اختبارات داخلية لا يُثبت صحة DSR/PBO إحصائيًا. قارن النتائج على عينات صناعية ذات توزيعات معروفة، وعلى نتائج Aurum، وتحقق من تصحيح عدد المحاولات والارتباط الذاتي قبل اعتماد أي صيغة.

**Metatrader-Bridge:** يحتوي على وظائف عرض الأسعار وإرسال أوامر، ولم نعثر على اختبارات آلية في المصدر المؤرشف. لا تنقل وظائف فتح/إغلاق الأوامر ولا طبقة IPC نفسها إلى التنفيذ؛ ادرس تصميم نقل رسائل الأسعار فقط، مع إضافة المصادقة وحظر الأوامر وتصفية الرمز والمهلة والتزامن واكتشاف تكرار الرسائل. الأفضل إبقاء جسر MT5 الذي نطوره نحن للقراءة فقط إلى أن ينجح اختبار broker demo رسمي.

## طريقة الاستفادة الآن

- **ليس كحزمة Python جديدة**، ولا كـ `pip install -e vendor/research_refs/*`.
- ارجع إلى الملفات هنا لمقارنة الخوارزميات/الأفكار، ثم اكتب adapter أو تنفيذًا داخليًا مستقلًا مع اختبارات تستند إلى حالات مرجعية.
- أي نقل فعلي للشيفرة إلى النواة يتطلب ADR، اختبارات صحيحة، تدقيق الرخص والاعتماديات، ومعايير قبول جديدة.
- لا تستخدم كلمة `ready` أو `approved` لهذين المصدرين: **reference only**.

## ما لا يزال ناقصًا لتسريع الهدف

تثبيت Pandera/MLForecast بنسخ حزم قابلة لإعادة الإنتاج بعد اختيار بيئة التنفيذ، وتشغيل MT5 المحلي للقراءة وتحديد مواصفات الذهب ووقت خادم الوسيط، والحصول على بيانات Tick/Bid/Ask مغطاة زمنيًا. هذه أهم من نقل مزيد من الشيفرة.
