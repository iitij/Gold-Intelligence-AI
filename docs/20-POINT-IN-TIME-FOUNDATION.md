# أساس بناء ميزات سببية وتوسيم محافظ — XAUUSD

**الحالة:** بحث أولي يختبر بيانات اصطناعية فقط، وليس نموذجًا مدربًا أو مجموعة بيانات جاهزة أو استراتيجية تداول.

## المكونات
- `src/goldintel/research/point_in_time.py`: لا يقبل سوى XAUUSD وM15/H1/H4 وأوقات UTC صريحة؛ يتحقق من صلاحية OHLC وتوقيت اكتمال الشمعة وإتاحتها.
- `make_gold_features`: لا يستخدم إلا شموعًا مكتملة و**متاحة عند لحظة القرار**. يرفض تكرار الشموع، وعدم تتابع M15 المستخدمتين للعائد، وقدم السوق. الميزات: عائد M15 السابق، المدى، جسم الشمعة، وآخر سعر إغلاق تاريخي للأطر المطلوبة. **لا يدخل أي تسميات أو عوائد مستقبلية في المدخلات**.
- `EconomicObservation` و`latest_released_observations`: يفرقان بين تاريخ المرجع وتاريخ النشر الفعلي، ويمنعان استعمال مراجعة ماكرو أو تقرير COT لم يكن منشورًا قبل القرار.
- `src/goldintel/research/labeling.py`: وسوم **افتراضية** TARGET / STOP / TIMEOUT / AMBIGUOUS عند مراقبة *شموع مستقبلية* لا تظهر في مدخلات التدريب، مع رفض الغموض أو فجوات السلسلة.

## حدود السلامة العلمية
1. **التوسيم على OHLC ليس محاكاة تنفيذ**. إذا لامست شمعة واحدة الهدف والوقف، نرجع `AMBIGUOUS` لأن ترتيب لمس الحاجزين لا يُعرف. حتى لمس هدف وحده لا يضمن تنفيذًا بسعر الوسيط، ولا عائدًا بعد العمولات والسبريد والانزلاق. لذلك `executable_pnl_verified=False`.
2. **لا توجد بيانات وسيط حقيقية**. نحتاج بيانات Tick/Bid/Ask وتوقيت خادم الوسيط الموثق وتحويل DST ومواصفات العقد قبل اعتباره صالحًا لتدريب التداول.
3. `available_at_utc` يجب أن يراعي متى استطاعت منظومتنا الوصول للبيانات، وليس مجرد موعد النشر الرسمي. الأخبار المجدولة تختلف عن نتائج أحداث جرى نشرها.
4. هذه الدوال صغيرة وعملها في الذاكرة وغير محسنة لملايين السجلات. لا تحل محل مخزن خصائص أو Dataset/Splits وPurging.
5. لا يجوز للوكيل اللغوي أو التنفيذ استدعاء `hypothetical_barrier_label` عند اتخاذ قرار حي؛ الوسوم للمراجعة التاريخية فقط.

## تشغيل الاختبارات
```bash
python -m pytest tests/test_point_in_time.py tests/test_research_labeling.py -q
```

**مسار العمل المتبقي:** P03-01..P03-06 (توثيق بيانات السوق) → P04-01 (الخصائص) → P04-02 (توسيم قابل للتنفيذ على Tick) → P04-03 (Dataset + Purging) → P05 (خطوط أساس وتدريب حقيقي) → P08 (Walk-Forward وقبول النتيجة الاقتصادية).

هذه خطوة بحثية مدققة باستخدام بيانات اصطناعية؛ لا تغلق وحدها مهام التدريب أو البيانات أو الاختبار الفعلي.

## امتداد فصل عينات التدريب والاختبار

- `src/goldintel/research/splits.py`: نموذج `LabeledInterval` يحتوي موعد القرار، نهاية أفق التسمية، ووقت ظهور النتيجة بالفعل.
- `build_anchored_fold`: يقبل Train cutoff وTest window وEmbargo محددة؛ لا يقبل عينة تدريب تعتمد نتيجتها على فترة الاختبار أو تأخر وصولها إلى ما بعد بدء الاختبار، ويستبعد عينات الاختبار التي لم تكتمل نتائجها حتى نهايته.
- تستبعد الدالة عينات الفجوة والبيانات المستقبلية والتكرارات، وتعيد معرفات عينات فقط، دون تدريب أي نموذج.
- **الحدود:** هذا Split واحد للأبحاث ولا يشكل وحده Walk-Forward شاملًا أو اختيار متغيرات أو Calibration داخل Fold أو إدارة Holdout مغلق. يجب لاحقًا كتابة Model Trainer وفصل التحويلات والحسابات الإحصائية لمنع تسربها.

```bash
python -m pytest tests/test_research_splits.py -q
```
